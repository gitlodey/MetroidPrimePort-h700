# H700 — от работающего renderer к полной игре

**Утверждено пользователем, 2026-11-16. Локальные GM-01…GM-17 разрешены, после каждой завершённой итерации — commit/push. Device-окна согласуются отдельно.** Полная рабочая версия: [H700_GAME_PLAN.md](H700_GAME_PLAN.md).

## Что уже есть

Новая графическая основа работает на RG40XX H: последний корректный ручной запуск интеграционной сцены прошёл, пользователь увидел изображение через Ports. Это важная опора, но **не запущенная полная игра**. Три других ручных запуска остались неполными по проверке пересечения потоков; ограничения не скрыты в [отчёте](H700_INTEGRATION_GATE.md). Повторять демку ради идеальной таблицы не предлагаем.

## Что предлагаем сделать дальше

1. **Собрать настоящий игровой executable.** Не ещё одну демку, а всю новую базу v0.46.0, с теми же закреплёнными зависимостями и воспроизводимым offline-рецептом.
2. **Безопасно подключить игру к renderer.** При reset/выходе сначала дождаться использования игровых данных, затем уничтожить объекты и дождаться работы их деструкторов. Только потом закрывать графическую систему. При аварии не освобождать данные работающих потоков и не выдавать timeout за успех.
3. **Задать профиль для устройства с 1 GB памяти.** Оригинальные ресурсы, 640×480/4:3, без HD/PBR и дополнительных тяжёлых улучшений. Все штатные эффекты, visors, вода/прозрачность и отражения сохраняются. Размеры из исходников ещё не говорят, сколько памяти займёт реальная сцена: проверим это на маршруте.
4. **Упаковать отдельную установку Ports.** Свой executable и своя папка настроек/карт/кэша, сохраняемая между окнами приёмки по одному стабильному пути. Старый порт и личные сохранения не меняем. Сохраняем штатные исправления управления, аудио и безопасной записи файлов новой базы.
5. **Принять реальную игру в трёх отдельно разрешённых окнах.** Не ограничиваться заставкой: управление, звук, эффекты, переходы между комнатами, reset, сохранение на станции и загрузка в новом процессе.

## Что утверждено

В подробном плане обозначены решения D1…D11. Самые существенные:

- **Существующий builder:** использовать тот же точный ARM64 image для сборок и локальных проверок correctness RC этого плана, включая повторную fresh build. Его Ubuntu уже EOL; для демки это было разрешено, для полной игры просим явное расширение разрешения. Если toolchain несовместим, остановимся — не будем молча менять image/Dawn/nod или ставить Rust.
- **Первый игровой профиль:** offline GameCube, без WSS/Archipelago-приёмки; настоящий nod, без заглушки. Один выбранный вами законный disc image, без копирования игровых данных в пакет.
- **Память:** MEM1 24 MiB, отключён резерв под дополнительные room assets, scale1 без принудительной полной allocation, lazy pipelines. Начальные пороги освобождения неиспользуемых pipelines — 192/128 MiB свободной памяти; проверяемый запас — не ниже96 MiB по samples. Это предложения, не доказанный бюджет. При нехватке памяти — отчёт и пересмотр, не отключение штатных эффектов или добавление swap.
- **Управление/выход:** Modern/twin-stick; Back+Start открывает PortMenu, оттуда Quit. Звук со штатным балансом. Cap30 при simulation60 — только начальная настройка, **не обещание достигнутых30FPS**.
- **Сохранения:** новая отдельная card, без quick-resume и общей карты со старым портом. Проверяем именно station save → нормальный выход → новый процесс → CARD load.
- **Авария:** если поток/драйвер завис, нельзя безопасно освободить его данные лишь по истечении таймера. Такой запуск — FAIL/partial, принудительное завершение отдельно согласуется. Не вводим автоматический kill во время записи карты.

Пользователь утвердил план целиком, включая локальные **GM-01…GM-17**. При необходимости изменить решения или границы работ останавливаемся и согласуем изменение; device-окна всё равно требуют отдельных разрешений.

## Как проверяем на приставке

| Окно | Содержание | Предлагаемый предел |
| --- | --- | --- |
| A | Запуск через Ports, logo/movie, новая игра, движение/стрельба, изображение/HUD, слышимый звук, PortMenu и нормальный выход | До20мин |
| B | Повторяемый маршрут/переходы, память, reset; запись на станции, выход и загрузка в новом процессе, сохранность настроек | До30мин |
| C | Штатные материалы/эффекты, Scan/Thermal/X-ray, полный набор кнопок, UI и audio checklist | До30мин на подготовленных сценах |

Каждое окно требует **отдельного разрешения**. Чтобы проверить поздние visors, заранее выбираем доступ: естественно достигнутое сохранение либо разрешённая частная тестовая копия, не перезапись личных файлов. Если сцены недоступны, соответствующая приёмка остаётся pending. Естественное прохождение к ним не входит в эти короткие окна.

Лимит времени — не команда убить игру. При зависании или нехватке памяти не продолжаем нагрузку и не прерываем CARD write. Прошивку, системные библиотеки, частоты, swap, микшер и службы не меняем.

## Объём и результат

**21 небольшая карточка; ориентир около30–42 часов активной работы**, без ожидания полных сборок, доступа к приставке и прохождения к поздним сценам. Это не гарантия срока: неизвестный build/runtime blocker потребует остановки и отдельного решения, а не скрытого расширения задачи.

На выходе — проверенный пакет новой игры для нашей RG40XX H/Jacaranda, рецепт его сборки/установки и честный отчёт о пройденных сценах и ограничениях. Не обещаем прохождение всей кампании, поддержку всех версий диска или других устройств. **Оптимизацию к стабильным30FPS начинаем отдельным планом после этой приёмки.**

Текущий статус: **GM-01/02 LOCAL PASS — root configure и первая полная compile/link прошли, `--version` работает без графики. GM-03 — игровой профиль H700 — также LOCAL PASS: новые defaults, unpinned allocation, защита Dawn checks и отказ от конфликтующих overrides. Следующий шаг GM-04 — pressure/RAM diagnostics.** Фактические результаты — в [прогрессе](H700_PROGRESS.md) и подробном плане; device tests не начаты.
