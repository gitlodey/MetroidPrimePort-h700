# H700 — находки для последующей оптимизации

Цель будущего этапа — стабильные **30 FPS при 640×480, 4:3** на RG40XX H / muOS 2601.0 Jacaranda. Сначала выполняется перенос с правильной картинкой, интерфейсом, управлением, звуком и сохранениями. Этот документ — список оснований для будущих экспериментов, **не план уже разрешённых изменений**.

Источники исходных наблюдений OPT-001…005 — [технический обзор](H700_PORT_REVIEW.md) и исторический bring-up. Fresh game evidence RC5 вынесено отдельно в OPT-006; его нельзя смешивать с наблюдениями старого renderer. После RC5 пользователь запросил приоритет производительности из-за неиграбельности; конкретный optimization plan/production changes ещё не утверждены.

## Правила записей

**До начала любой гипотезы/исследования/эксперимента пройти [goal gate](H700_WORKFLOW.md):** конкретная польза для RG40XX H / muOS 2601, evidence применимости, минимальная проверка и решение, которое изменит её результат. Во время переноса находку можно записать, но нельзя начинать оптимизацию или расширять окружение ради любопытства/полноты.

Для каждой находки сохранять стабильный ID, основание, гипотезу, способ будущей проверки, риски и статус. Не превращать предположение в обещанный прирост FPS. Эксперимент и его включение в работу согласуются отдельно по [H700_WORKFLOW.md](H700_WORKFLOW.md).

## OPT-001 — затраты процессора, драйвера и ожидания

- **Основание:** исторический профиль тяжёлого боя показал существенную работу нескольких CPU threads, но не непрерывную полную загрузку всех ядер/GPU. Снижение внутреннего разрешения не дало заметного пользователю улучшения.
- **Гипотеза:** значимая часть задержек может находиться в подготовке/отправке команд, драйвере или синхронизации, а не только в количестве пикселей.
- **Будущая проверка:** повторяемая сцена и continuous frametimes, отдельно simulation/record/decode/replay/present/wait; CPU time не смешивать с wall time, перекрывающиеся потоки не складывать.
- **Риск:** смешанные сцены/визоры и driver utilization не позволяют назвать один виновный компонент. Замер может влиять на результат.
- **Статус:** гипотеза по старому порту; причина не установлена.

## OPT-002 — повторная обработка и загрузка геометрии

- **Основание:** донор использует native vertex attributes и cache подготовленной геометрии; новая база имеет другие механизмы повторного использования данных. В доноре найден дефект invalidation при изменении массива внутри кадра.
- **Гипотеза:** уменьшение повторного преобразования/копирования может сократить CPU и upload work.
- **Будущая проверка:** измерить стоимость и cache hit rate в выбранной архитектуре; сравнивать только варианты, проходящие тесты lifetime/invalidation и визуальную проверку.
- **Риск:** неверный cache рисует старые данные; его память и hashing могут стоить больше выигрыша. Дублирование cache новой базы не гарантирует пользу.
- **Статус:** кандидат, не рекомендация переносить cache донора целиком.

## OPT-003 — очереди кадров и синхронизация

- **Основание:** донор использует два slots, несколько graphics contexts и ожидания между rendering/present. Его упрощение FIFO отличается от новой базы.
- **Гипотеза:** организация overlap и ожиданий может заметно влиять на время кадра.
- **Будущая проверка:** записать длительность и причины ожиданий на каждом участке, затем сравнить согласованные варианты при одинаковой сцене и условиях.
- **Риск:** удаление fence/drain/token ради скорости может вернуть повреждение геометрии и гонки. «Не ждать» не является безопасной оптимизацией.
- **Новое evidence, 2026-11-14:** [демка Dawn/EGLImage](H700_GRAPHICS_PROBE.md) прошла 120 кадров bridge на Mali-G31. Её single-image путь намеренно включает queue completion, diagnostic readbacks, presenter `glFinish` и sleep 100 ms на кадр. Это correctness baseline, не benchmark; время 13.059 s нельзя переводить в игровой FPS.
- **Следствие для будущих измерений:** отдельно измерять transfer/sync/driver wait и диагностические stalls; после correctness сравнивать согласованную bounded slot/fence policy без покадрового diagnostic readback. Не удалять waits вслепую и не принимать демку за готовую production frame loop.
- **Статус:** потенциальное направление, применимость зависит от выбранной интеграции; оптимизация не реализовывалась.

## OPT-004 — ограничение памяти и прогрев caches

- **Основание:** общая RAM около 1 GB без swap; в доноре большие reserves, nominal replacement cache 4 GiB и не везде ограниченный runtime program cache. Новая база содержит более развитые memory policies.
- **Гипотеза:** разумные бюджеты и повторное использование shader programs могут уменьшить spikes/stutter и снизить риск нехватки памяти.
- **Будущая проверка:** peak RSS, driver allocations при доступной метрике, high-water marks, cold/warm runs и длительная игра. Сохранять проверку корректности при eviction.
- **Риск:** чрезмерное уменьшение cache вызывает повторные загрузки/компиляции; резервируемая память не равна измеренной resident memory. Исправление correctness/безопасности памяти при переносе не нужно откладывать под видом оптимизации.
- **Уточнение по sources, 2026-11-14:** [pinned Dawn с U thread toggle](H700_DAWN_INTEGRATION_GAPS.md) при `GLAllowContextOnMultiThreads && !GLDefer` создаёт до четырёх shared compiler contexts, хотя Aurora OpenGLES использует один compiler worker. Их фактическое число и RAM/driver cost на Mali не измерены. После correctness имеет смысл измерить allocations/cold compile/context costs, не менять dependency или число contexts ради предположительного выигрыша.
- **Статус:** направления измерения; конкретные бюджеты не назначены.

## OPT-005 — стоимость необязательных улучшений

- **Основание:** input/QoL обычно не добавляет graphics passes; anisotropy 2× может быть недорогой. Дополнительные тени, MSAA и повторный рендер мира имеют другую цену. `Original Experience` не является готовым минимальным профилем.
- **Гипотеза:** после базовой оптимизации часть улучшений удастся сохранить без заметной потери скорости.
- **Будущая проверка:** включать по одному в одинаковых сценах, сравнивать frametimes и память. Штатные визоры, прозрачность и другие оригинальные эффекты не считать необязательными улучшениями.
- **Риск:** дешёвая функция может менять gameplay; низкая теоретическая стоимость не доказывает отсутствие нагрузки на конкретном драйвере.
- **Статус:** отложено до корректной базовой версии и измерений.

## OPT-006 — RC5: неиграбельная отзывчивость, draw/compile stalls

- **Fresh evidence, 2026-11-17:** RC5 archive SHA256 `fd024470098b5f3556a02f3107a7eebdd249b7b28cf21ee889e378fac05f2240`, собственная warm/update installation. За5мин bounded observation процесса, запущенного с меню, прежний trace-exhaustion не повторился; later stall log дошёл до frame4465 без observed backend errors/fail-stop. Пользователь сообщил, что UI настолько медленный, что нельзя отличить input defect от задержки; сам начал New Game и оценил графику начального ролика как очень хорошую. Момент перехода к New Game в observation не помечен; это не раздельный benchmark меню/ролика и не gameplay/input/save/load acceptance.
- **Измеренное:** интервал1500frames дал9,1FPS (не steady-state конкретной сцены); в последних samples frame837–1077ms, из них draw803–1042ms, tick33–37ms, events/input округлены до0ms. Есть pipeline compile warnings1019/1034ms. Эти overlapping wall intervals нельзя складывать и объявлять одной установленной причиной всей медленной работы.
- **Что означает draw:** main-loop timer охватывает путь после tick до workEnd, включая ожидания/подготовку/EndScene; это не GPU execution time. В sources `find_pipeline_impl` может ждать Blocking compile, а `require_pipeline_impl` вызывается для VFX/water; direct dependency требует проверки применимости именно к этому run. `get_pipeline` diagnostic RenderWait включён только при IG Control и не описывает retail wait автоматически.
- **Память:** в usability snapshot MemAvailable198272KiB (~194MiB), logged sampled minimum196596KiB (~192MiB), process742MiB при Dawn~322MiB; перед остановкой также наблюдались~182MiB available. Менялись сцены (menu→New Game/intro), поэтому рост не объявлен leak. После отдельно разрешённого одного SIGTERM game/copier/launcher завершились, lock снялся, MemAvailable823936KiB (~805MiB). Это не normal Exit acceptance; новый маршрут/нагрузка не запускались.
- **Первый вопрос следующего этапа:** отдельно установить причины low-FPS уже используемого menu/render path и длинных stalls при появлении новых pipelines — CPU recording, pipeline/cache/driver compilation или waits. Не выводить GPU-bound из одного draw timer и не обещать прирост от prewarm/cache без проверки hit/miss/rebuild path.
- **Границы:** original graphics/effects и существующие lifetime/validation/robustness guards сохраняются; firmware/clocks/swap не меняются. Сначала узкая причина/план correction с воспроизводимым сравнением, не новый profiler framework и не новый круг hardware/backend research.
- **Уточнение при подготовке плана:** полный final log содержит82slow-compile warnings на82разных hashes,217–2507ms (медиана782,5ms только среди warnings),0blocking draw-wait warnings и64capped new-miss lines. Это не доказывает повторную компиляцию одного hash или единственную причину stalls. В pinned Dawn найден настоящий current-context/nested fast path; observer его не отключает. Время ledger/driver/context waits по текущему логу не выделено.
- **Следующий минимальный шаг — [PERF-01, проект для утверждения](H700_PERFORMANCE_PLAN.md):** один неизменённый warm RC5 run,180s фиксированного меню и пассивные CPU/state/wchan samples игровых TID плюс existing log. Без новой сборки/новых timers/изменения cache/установки tools. По данным выбрать один адресный source path; не обещать заранее FPS fix. Production changes и device run этим проектом не разрешены.
- **Статус:** usability FAIL по пользователю; подготовка первого performance-плана выполнена по запросу, сам PERF-01 ещё не утверждён. Production optimization не начата; RC5/его data не изменялись. Raw evidence — ignored `build/h700-game-a3-rc5/usability-summary.json`, `termination-result.json` и связанные logs. Final log сохранён после завершения copier,5firmware baseline hashes unchanged; новое performance code/device experiment ещё не выполнялось.
