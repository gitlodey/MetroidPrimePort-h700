# H700 — находки для последующей оптимизации

Цель будущего этапа — стабильные **30 FPS при 640×480, 4:3** на RG40XX H / muOS 2601.0 Jacaranda. Сначала выполняется перенос с правильной картинкой, интерфейсом, управлением, звуком и сохранениями. Этот документ — список оснований для будущих экспериментов, **не план уже разрешённых изменений**.

Источники исходных наблюдений — [технический обзор](H700_PORT_REVIEW.md) и описанный в нём исторический bring-up. Ниже нет новых бенчмарков; новая база на приставке пока не измерялась. Наблюдения старого renderer нельзя автоматически переносить на новый вариант интеграции.

## Правила записей

Для каждой находки сохранять стабильный ID, основание, гипотезу, способ будущей проверки, риски и статус. Не превращать предположение в обещанный прирост FPS. Эксперимент и его включение в работу согласуются отдельно по [H700_WORKFLOW.md](H700_WORKFLOW.md).

## OPT-001 — затраты процессора, драйвера и ожидания

- **Основание:** исторический профиль тяжёлого боя показал существенную работу нескольких CPU threads, но не непрерывную полную загрузку всех ядер/GPU. Снижение внутреннего разрешения не дало заметного пользователю улучшения.
- **Гипотеза:** значимая часть задержек может находиться в подготовке/отправке команд, драйвере или синхронизации, а не только в количестве пикселей.
- **Будущая проверка:** повторяемая сцена и continuous frametimes, отдельно simulation/record/decode/replay/present/wait; CPU time не смешивать с wall time, перекрывающиеся потоки не складывать.
- **Риск:** смешанные сцены/визоры и driver utilization не позволяют назвать один виновный компонент. Замер может влиять на результат.
- **Статус:** гипотеза по старому порту; причина не установлена.

## OPT-002 — повторная обработка и загрузка геометрии

- **Основание:** донор использует native vertex attributes и cache подготовленной геометрии; новая база имеет другие механизмы повторного использования данных. В доноре найден дефект invalidation при изменении массива внутри кадра.
- **Гипотеза:** уменьшение повторного преобразования/копирования может сократить CPU и upload work.
- **Будущая проверка:** измерить стоимость и cache hit rate в выбранной архитектуре; сравнивать только варианты, проходящие тесты lifetime/invalidation и визуальную проверку.
- **Риск:** неверный cache рисует старые данные; его память и hashing могут стоить больше выигрыша. Дублирование cache новой базы не гарантирует пользу.
- **Статус:** кандидат, не рекомендация переносить cache донора целиком.

## OPT-003 — очереди кадров и синхронизация

- **Основание:** донор использует два slots, несколько graphics contexts и ожидания между rendering/present. Его упрощение FIFO отличается от новой базы.
- **Гипотеза:** организация overlap и ожиданий может заметно влиять на время кадра.
- **Будущая проверка:** записать длительность и причины ожиданий на каждом участке, затем сравнить согласованные варианты при одинаковой сцене и условиях.
- **Риск:** удаление fence/drain/token ради скорости может вернуть повреждение геометрии и гонки. «Не ждать» не является безопасной оптимизацией.
- **Статус:** потенциальное направление, применимость зависит от выбранной интеграции.

## OPT-004 — ограничение памяти и прогрев caches

- **Основание:** общая RAM около 1 GB без swap; в доноре большие reserves, nominal replacement cache 4 GiB и не везде ограниченный runtime program cache. Новая база содержит более развитые memory policies.
- **Гипотеза:** разумные бюджеты и повторное использование shader programs могут уменьшить spikes/stutter и снизить риск нехватки памяти.
- **Будущая проверка:** peak RSS, driver allocations при доступной метрике, high-water marks, cold/warm runs и длительная игра. Сохранять проверку корректности при eviction.
- **Риск:** чрезмерное уменьшение cache вызывает повторные загрузки/компиляции; резервируемая память не равна измеренной resident memory. Исправление correctness/безопасности памяти при переносе не нужно откладывать под видом оптимизации.
- **Статус:** направления измерения; конкретные бюджеты не назначены.

## OPT-005 — стоимость необязательных улучшений

- **Основание:** input/QoL обычно не добавляет graphics passes; anisotropy 2× может быть недорогой. Дополнительные тени, MSAA и повторный рендер мира имеют другую цену. `Original Experience` не является готовым минимальным профилем.
- **Гипотеза:** после базовой оптимизации часть улучшений удастся сохранить без заметной потери скорости.
- **Будущая проверка:** включать по одному в одинаковых сценах, сравнивать frametimes и память. Штатные визоры, прозрачность и другие оригинальные эффекты не считать необязательными улучшениями.
- **Риск:** дешёвая функция может менять gameplay; низкая теоретическая стоимость не доказывает отсутствие нагрузки на конкретном драйвере.
- **Статус:** отложено до корректной базовой версии и измерений.
